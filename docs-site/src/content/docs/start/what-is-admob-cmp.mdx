## What is AdMob CMP?

AdMob CMP is an open-source Kotlin Multiplatform (KMP) SDK for Google AdMob in Compose Multiplatform applications. It provides one shared Kotlin API for Google Mobile Ads (GMA), User Messaging Platform (UMP) consent state, ad loading, presentation, and revenue events on Android and iOS.

Instead of maintaining separate Android and iOS ad abstractions, add `dev.avinya.ads:admob-cmp:2.1.0` and call the same controllers from `commonMain`. Native application IDs, store disclosures, consent configuration, and iOS package setup remain the application's responsibility.

## Why use AdMob CMP?

The SDK standardizes the parts of an AdMob integration that otherwise need separate platform implementations:

1. **Shared controllers**: Load and show ads from common Kotlin without duplicating controller logic in Swift and Android source sets.
2. **Compose surfaces**: Render banners and native ads with `BannerAdView` and `NativeAdView`.
3. **Explicit consent modes**: Gather UMP consent before initialization, initialize only when consent already permits requests, or deliberately skip the SDK-managed consent step. The application still owns its consent message configuration, legal assessment, and store disclosures.
4. **Unified state and events**: Observe load state through `StateFlow` and receive lifecycle, click, impression, and paid events through `AdEvent`.
5. **Stable composition ownership**: `rememberAdManager()` and remembered controller lookups avoid recreation during recomposition. A controller or native session only outlives navigation disposal when the application owns it above that disposable destination.

## Ad formats supported

AdMob CMP supports all major Google Mobile Ads formats. Each format comes with a unified controller API and, where applicable, a ready-to-use Composable view.

| Format | Controller | Composable View | Guide |
|---|---|---|---|
| **Banner** (Standard & Adaptive) | `adManager.banner(placement)` | `BannerAdView` | [Banner ads](/formats/banner/) |
| **Interstitial** | `adManager.interstitial(placement)` | — | [Interstitial ads](/formats/interstitial/) |
| **Rewarded** | `adManager.rewarded(placement)` | — | [Rewarded ads](/formats/rewarded/) |
| **Rewarded Interstitial** | `adManager.rewardedInterstitial(placement)` | — | [Rewarded ads](/formats/rewarded/) |
| **App-Open** | `adManager.appOpen(placement)` | — | [App-open ads](/formats/app-open/) |
| **Native** | `adManager.nativeAds.session()` | `NativeAdView` | [Native ads](/formats/native/) |

## SDK Architecture

The library is split into two primary modules:
- `admob-cmp-core`: The engine. It manages the controllers, lifecycle state machines, ad caching logic, retry policies, and platform-specific adapters. Non-Compose KMP apps can depend on this directly.
- `admob-cmp-compose`: The UI layer. It provides the Compose Multiplatform abstractions, including `rememberAdManager()`, `BannerAdView`, and `NativeAdView`.

Platform specificities remain strictly isolated. Manifest metadata (`AndroidManifest.xml`) and application identity (`Info.plist`) stay native, while all ad management happens in your shared Kotlin code.

> **Mediation adapters are application dependencies.** Third-party adapters such as Meta or Unity are not bundled; add the required adapter to each native Android and iOS project.
