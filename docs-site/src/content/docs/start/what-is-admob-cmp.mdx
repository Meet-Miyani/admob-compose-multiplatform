## What is AdMob CMP?

AdMob CMP is a Kotlin Multiplatform (KMP) SDK that makes it easy to add Google AdMob to your Compose Multiplatform apps. It provides a unified Kotlin API for Google Mobile Ads (GMA) and User Messaging Platform (UMP) consent, letting you manage ad lifecycles, load states, and privacy compliance using declarative UI patterns you already know.

Instead of writing custom expect/actual bindings for iOS and Android separately, you can use one dependency—`dev.avinya.ads:admob-cmp:1.1.1`—to render ads across both platforms.

## Why use AdMob CMP?

Adding ads to a KMP project usually involves wrestling with native iOS dependencies, complex platform state synchronization, and strict GDPR consent lifecycles. AdMob CMP solves these headaches out of the box:

1. **Write Once, Monetize Anywhere**: Manage your ads entirely in shared Kotlin code. No need to write separate Swift and Kotlin integrations.
2. **Built for Compose**: Native support for Compose Multiplatform with composables like `BannerAdView` and `NativeAdView`.
3. **Built-in GDPR/UMP Consent**: Automatically gathers European Economic Area (EEA) and UK privacy consent before making ad network requests, preventing policy violations.
4. **Unified Event Streams**: Listen to ad events (like `Loaded`, `Clicked`, `Paid`) across both platforms through a single, clean `StateFlow`.
5. **Smart State Management**: Controllers survive UI recompositions automatically, preventing accidental ad reloads.

## Ad formats supported

AdMob CMP supports all major Google Mobile Ads formats. Each format comes with a unified controller API and, where applicable, a ready-to-use Composable view.

| Format | Controller | Composable View | Guide |
|---|---|---|---|
| **Banner** (Standard & Adaptive) | `adManager.banner(placement)` | `BannerAdView` | [Banner ads](/formats/banner/) |
| **Interstitial** | `adManager.interstitial(placement)` | — | [Interstitial ads](/formats/interstitial/) |
| **Rewarded** | `adManager.rewarded(placement)` | — | [Rewarded ads](/formats/rewarded/) |
| **Rewarded Interstitial** | `adManager.rewardedInterstitial(placement)` | — | [Rewarded ads](/formats/rewarded/) |
| **App-Open** | `adManager.appOpen(placement)` | — | [App-open ads](/formats/app-open/) |
| **Native** | `adManager.nativeAds.session()` | `NativeAdView` | [Native ads](/formats/native/) |

## SDK Architecture

The library is split into two primary modules:
- `admob-cmp-core`: The engine. It manages the controllers, lifecycle state machines, ad caching logic, retry policies, and platform-specific adapters. Non-Compose KMP apps can depend on this directly.
- `admob-cmp-compose`: The UI layer. It provides the Compose Multiplatform abstractions, including `rememberAdManager()`, `BannerAdView`, and `NativeAdView`.

Platform specificities remain strictly isolated. Manifest metadata (`AndroidManifest.xml`) and application identity (`Info.plist`) stay native, while all ad management happens in your shared Kotlin code.

> **Note on Medation**: To prevent dependency lock-in, third-party mediation adapters (like Meta or Unity) are not bundled. You must add them directly to your native Android/iOS projects.
