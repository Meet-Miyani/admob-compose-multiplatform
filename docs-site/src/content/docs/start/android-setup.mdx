This guide details the Android-specific configuration required to initialize and serve ads using AdMob CMP.

## Manifest configuration

Google Mobile Ads requires an Application Identifier declared in your Android application module's `AndroidManifest.xml`.

```xml
<!-- androidApp/src/main/AndroidManifest.xml -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <meta-data
            android:name="com.google.android.gms.ads.APPLICATION_ID"
            android:value="ca-app-pub-3940256099942544~3347511713" /> <!-- Replace with real App ID -->
    </application>
</manifest>
```

### Key requirements

- **Metadata Location**: Place `<meta-data>` inside the `<application>` tag of the runnable Android application module (`androidApp`), not inside a shared Kotlin library module.
- **Identifier Format**: Application IDs use a tilde separator (`ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX`). Providing an Ad Unit ID (which uses a slash separator) will cause initialisation failure or runtime crashes.
- **Runtime Enforcement**: Omitting `com.google.android.gms.ads.APPLICATION_ID` causes the Google Mobile Ads SDK to crash upon app launch.

## Managing the AD_ID permission

The Google Mobile Ads SDK transitively merges the `com.google.android.gms.permission.AD_ID` permission into your application manifest to access the Android Advertising ID on devices targeting API 33 (Android 13) or higher.

### Opting out for child-directed apps

If your application is child-directed or subject to strict privacy restrictions, remove the permission explicitly using manifest merging rules:

```xml
<!-- androidApp/src/main/AndroidManifest.xml -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">

    <uses-permission
        android:name="com.google.android.gms.permission.AD_ID"
        tools:node="remove" />
</manifest>
```

<Aside type="caution">
Removing `AD_ID` disables access to the device advertising identifier on Android 13+ devices, which affects ad personalisation. Ensure your Google Play Data Safety declaration accurately reflects the status of this permission.
</Aside>

## Android build requirements

AdMob CMP 2.0.1 is built and tested against the following toolchain specifications:

| Setting | Tested Version / Specification |
|---|---|
| Minimum SDK (`minSdk`) | API 26 (Android 8.0) |
| Compile SDK (`compileSdk`) | API 37 |
| Target SDK (`targetSdk`) | API 36 |
| Android Gradle Plugin (AGP) | 9.2.1 |
| Google Mobile Ads Next-Gen SDK | 1.3.0 (transitive) |
| User Messaging Platform SDK | 4.0.0 (transitive) |

### Repository resolution

Google Mobile Ads relies on Cronet dependencies hosted on Google's Maven repository. Ensure `google()` is included in your repository configuration:

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}
```

Missing `google()` repository configuration will result in unresolved dependency errors during Gradle build resolution.

## Registering test devices

To test live ad units during development without triggering invalid traffic violations on your AdMob account, register test device hashed IDs:

```kotlin
import dev.avinya.ads.GlobalRequestConfiguration

GlobalRequestConfiguration.testDeviceIds = listOf(
    "33BE2250B43518CCDA7DE426D04EE231" // Replace with device logcat test ID
)
```

During initialisation, check Android `logcat` output for log messages containing `Use RequestConfiguration.Builder.setTestDeviceIds(...)` to locate your test device hash.

## Verifying the Android integration

Verify your Android integration:

1. **Merged Manifest Inspection**: Open Android Studio's **Merged Manifest** tab on `AndroidManifest.xml` and confirm `com.google.android.gms.ads.APPLICATION_ID` is present.
2. **Process Singleton Verification**: Outside Compose, `AdMob.manager(context)` resolves to the same process-wide `AdManager` singleton as `rememberAdManager()`.
3. **Runtime Execution**: Launch the app on an Android emulator or device and confirm that `adManager.status` reaches `AdManagerStatus.Ready`.
