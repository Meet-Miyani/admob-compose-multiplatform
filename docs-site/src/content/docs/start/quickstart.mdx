This quickstart guide will show you how to render your first test ad unit on Android and iOS using Compose Multiplatform. We'll also cover the steps required to transition from a test environment to a full production launch.

## 1. Add the dependency

First, add the core AdMob CMP library to your shared Kotlin module.

```kotlin
// shared/build.gradle.kts
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("dev.avinya.ads:admob-cmp:2.0.1")
        }
    }
}
```

This brings in the Google Mobile Ads (GMA) Next-Gen and User Messaging Platform (UMP) SDKs automatically for Android via Maven. For iOS, you'll need to link the native frameworks in Xcode via Swift Package Manager; see our [iOS setup guide](/start/ios-setup/) for details.

If your project runs Kotlin/Native unit tests (`:shared:iosSimulatorArm64Test`), apply our Gradle plugin to prevent linker errors:

```kotlin
// shared/build.gradle.kts
plugins {
    id("dev.avinya.ads.admob-cmp") version "2.0.1"
}
```

For full setup instructions (including version catalogs), check out the [Installation guide](/start/installation/).

## 2. Configure test app IDs

Google Mobile Ads requires a valid Application Identifier declared in your native platform files before initialisation. While developing, **always use Google's official test IDs** to avoid account suspension.

On **Android**, add this metadata entry to your `androidApp/src/main/AndroidManifest.xml`:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <meta-data
            android:name="com.google.android.gms.ads.APPLICATION_ID"
            android:value="ca-app-pub-3940256099942544~3347511713" />
    </application>
</manifest>
```

On **iOS**, add the application identifier to your `iosApp/iosApp/Info.plist`:

```xml
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-3940256099942544~1458002511</string>
```

## 3. Show your first test banner

Now let's render an ad! In your top-level `@Composable` entry point, you'll grab the process-wide `AdManager` singleton using `rememberAdManager()`. 

Use a `LaunchedEffect` to initialize it with test configuration, and then display a `BannerAdView`.

```kotlin
import androidx.compose.runtime.CompositionLocalProvider
import dev.avinya.ads.LocalAdManager

@Composable
fun App() {
    val adManager = rememberAdManager()

    LaunchedEffect(adManager) {
        adManager.gatherConsentAndInitialize(
            AdConfig(
                androidAppId = TestAdIds.ANDROID_APP_ID,
                iosAppId = TestAdIds.IOS_APP_ID,
                testMode = true,
            )
        )
    }

    val status by adManager.status.collectAsState()
    if (status is AdManagerStatus.Ready) {
        CompositionLocalProvider(LocalAdManager provides adManager) {
            MainAdScreen()
        }
    }
}

@Composable
fun MainAdScreen() {
    val placement = remember {
        AdPlacement(
            id = "main_banner",
            format = AdFormat.Banner,
            androidAdUnitId = TestAdIds.ANDROID_BANNER,
            iosAdUnitId = TestAdIds.IOS_BANNER,
            strictTestMode = true, // Protects you from serving live ads in debug
        )
    }

    BannerAdView(
        placement = placement,
        modifier = Modifier.fillMaxWidth(),
        onEvent = { event ->
            when (event) {
                is AdEvent.Loaded -> println("Test banner loaded successfully")
                is AdEvent.LoadFailed -> println("Test banner failed to load: ${event.error}")
                else -> Unit
            }
        },
    )
}
```

> **Tip**: Setting `strictTestMode = true` on the placement acts as a safety net. It will throw an exception if you accidentally deploy a non-test ad unit ID in a debug build!

## 4. Verify the ad renders

Run your application on an Android emulator or iOS simulator. 
1. The `adManager.status` should transition from `Initializing` to `Ready`.
2. A banner saying **"Nice job! This is an ad title"** will appear on the screen.
3. Check your console logs for the `Test banner loaded successfully` message.

## Going to Production

Transitioning from local tests to a live app requires setting up legal consent flows (like GDPR) and Apple's App Tracking Transparency (ATT).

### The Initialization Sequence

Production ad requests in GDPR regions or on iOS require explicit user consent. The SDK manages this flow in a strict sequence:

<InitSequence />

1. **User Messaging Platform (UMP)**: Asks for European Economic Area (EEA) and UK privacy consent.
2. **App Tracking Transparency (ATT)**: On iOS, requests authorization to access the Identifier for Advertisers (IDFA).
3. **GMA Initialization**: Initialises the Google Mobile Ads SDK based on the user's choices.

To handle this cleanly, you can register an `AdInitializationHook` that runs right before native SDK initialization to prompt for ATT on iOS:

```kotlin
@Composable
fun ProductionApp() {
    val adManager = rememberAdManager()
    val status by adManager.status.collectAsState()

    val config = remember(adManager) {
        AdConfig(
            androidAppId = "ca-app-pub-YOUR_PUBLISHER_ID~YOUR_ANDROID_APP_ID",
            iosAppId = "ca-app-pub-YOUR_PUBLISHER_ID~YOUR_IOS_APP_ID",
            testMode = false,
            initializationHooks = listOf(
                object : AdInitializationHook {
                    override suspend fun onPhase(
                        phase: AdInitializationPhase,
                        config: AdConfig,
                    ) {
                        if (phase == AdInitializationPhase.BeforeMobileAdsInitialize) {
                            // Prompt for ATT on iOS
                            adManager.tracking.requestAuthorization()
                        }
                    }
                }
            ),
        )
    }

    LaunchedEffect(adManager, config) {
        // Automatically gathers UMP consent (showing a form if required) and then initialises
        adManager.initialize(
            config = config,
            consentMode = ConsentMode.GatherBeforeInitialize,
        )
    }

    when (status) {
        AdManagerStatus.Ready -> {
            CompositionLocalProvider(LocalAdManager provides adManager) {
                ContentScreen(adManager)
            }
        }
        is AdManagerStatus.Failed -> ErrorScreen(status as AdManagerStatus.Failed)
        else -> LoadingScreen()
    }
}
```

*(Note: On Android, `requestAuthorization()` resolves immediately as `NotApplicable`, so it's safe to run on both platforms).*

### Production Launch Checklist

Before shipping to the App Store and Google Play, make sure you've completed these steps:

<Steps>

1. **Register Applications in AdMob Console**
   Create separate Android and iOS app entries in your Google AdMob account to get your production Application IDs.

2. **Create Production Ad Units**
   Generate placement-specific Ad Unit IDs for your ad formats (Banner, Interstitial, Rewarded, Native) in the AdMob console.

3. **Configure Privacy & Messaging**
   Set up GDPR/TCF consent forms and US state privacy messages in the AdMob console. UMP needs this to present valid consent dialogs.

4. **Update Metadata & Code**
   Replace the sample Application IDs in your `AndroidManifest.xml` and `Info.plist`, and inject your live `AdPlacement` identifiers into your Kotlin code.

5. **Configure iOS App Tracking Transparency**
   Add `NSUserTrackingUsageDescription` to your `Info.plist`. Double-check that your `requestAuthorization()` hook executes before native initialisation.

6. **Complete Store Privacy Disclosures**
   Fill out Google Play Data Safety and Apple App Store Privacy Nutrition Labels detailing how the SDK uses data. (Read our [Play Data safety guide](/privacy/play-data-safety/)).

7. **Register Test Devices**
   To safely test live ad units during development without risking an account ban, add your physical device IDs via `GlobalRequestConfiguration.testDeviceIds` or `AdDebugOptions.testDeviceIds`.

8. **Validate Release Builds**
   Test your signed release builds on physical iOS and Android devices before submitting!

</Steps>
