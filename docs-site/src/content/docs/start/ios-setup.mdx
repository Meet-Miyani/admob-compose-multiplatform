This guide covers the iOS setup required for AdMob CMP, including framework linkage via Swift Package Manager (SPM), `Info.plist` keys, App Tracking Transparency (ATT) initialisation hooks, and diagnostic checks.

## How the iOS frameworks are linked

AdMob CMP distributes Objective-C cinterop bindings in its Kotlin Multiplatform binaries without embedding Google's static framework binaries. The host iOS application links the native SDKs directly using Swift Package Manager.

### Swift Package Manager setup

<Steps>

1. In Xcode, open your iOS project and select **File → Add Package Dependencies...**
2. Enter the Google Mobile Ads SPM repository URL:
   `https://github.com/googleads/swift-package-manager-google-mobile-ads.git`
   Select the **GoogleMobileAds** product and specify version rule **Up to Next Major** with **13.x** (AdMob CMP 2.2.0 binds GMA iOS 13.7.0).
3. Enter the User Messaging Platform SPM repository URL:
   `https://github.com/googleads/swift-package-manager-google-user-messaging-platform.git`
   Select the **GoogleUserMessagingPlatform** product and specify version rule **Up to Next Major** with **3.x** (AdMob CMP 2.2.0 binds UMP iOS 3.1.0).

</Steps>

### Linking JavaScriptCore

When compiling a static Kotlin framework target, Xcode autolinking may fail to pull in system dependencies required by Google Mobile Ads. Add `-framework JavaScriptCore` to your iOS app target's **Build Settings → Other Linker Flags** (`OTHER_LDFLAGS`):

```text
OTHER_LDFLAGS = $(inherited) -framework JavaScriptCore
```

Omitting this linker flag when using a static Kotlin framework results in `Undefined symbol: _OBJC_CLASS_$_JSContext` at link time.

## Info.plist configuration

Configure your iOS application target's `Info.plist` with required metadata keys:

```xml
<!-- iosApp/iosApp/Info.plist -->
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-3940256099942544~1458002511</string> <!-- Replace with real App ID -->

<key>SKAdNetworkItems</key>
<array>
    <dict>
        <key>SKAdNetworkIdentifier</key>
        <string>cstr6suwn9.skadnetwork</string>
    </dict>
    <!-- Add current SKAdNetwork identifiers provided by Google AdMob -->
</array>
```

- `GADApplicationIdentifier`: Application identifier with a tilde separator (`ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX`). Omitting this key, or leaving its value empty, crashes native GMA on launch. AdMob CMP validates it during `initialize()` preflight under `AdAppIdVerification.policy` (`FailWhenUnusable` default, `Strict`, `WarnOnly`).
- `SKAdNetworkItems`: Array of ad network identifiers enabling privacy-preserving ad attribution.

## App Tracking Transparency (ATT) setup

To request user authorisation for accessing the Identifier for Advertisers (IDFA) on iOS 14.5+, configure `Info.plist` and implement an initialisation hook.

### 1. System usage description string

Add `NSUserTrackingUsageDescription` to your `Info.plist`:

```xml
<key>NSUserTrackingUsageDescription</key>
<string>This identifier will be used to deliver personalised ads to you.</string>
```

<Aside type="caution">
Adding `NSUserTrackingUsageDescription` to `Info.plist` configures the iOS system description string; it does **not** trigger the ATT prompt by itself. The application must explicitly invoke `requestAuthorization()` programmatically prior to initialising Google Mobile Ads.
</Aside>

### 2. Pre-initialisation ATT hook

Invoke `adManager.tracking.requestAuthorization()` using an `AdInitializationHook` targeting the `BeforeMobileAdsInitialize` phase. This guarantees that ATT authorization is requested after UMP consent gathering but before native ad engine startup:

```kotlin
val config = AdConfig(
    androidAppId = "ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX",
    iosAppId = "ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX",
    initializationHooks = listOf(
        object : AdInitializationHook {
            override suspend fun onPhase(
                phase: AdInitializationPhase,
                config: AdConfig,
            ) {
                if (phase == AdInitializationPhase.BeforeMobileAdsInitialize) {
                    // Prompt for ATT authorisation on iOS
                    adManager.tracking.requestAuthorization()
                }
            }
        }
    ),
)
```

On non-iOS platforms, `requestAuthorization()` completes immediately without displaying a prompt.

## Kotlin/Native test cinterop linkage

Executing Kotlin/Native test tasks (such as `./gradlew :shared:iosSimulatorArm64Test`) invokes the Kotlin compiler directly without Xcode or SPM. Apply the `dev.avinya.ads.admob-cmp` Gradle plugin to your shared module to inject required framework search paths into test executables:

```kotlin
// shared/build.gradle.kts
plugins {
    id("dev.avinya.ads.admob-cmp") version "2.2.0"
}
```

The plugin downloads reference framework headers and configures test link tasks without altering your production Xcode framework outputs.

## Verifying the iOS integration

Verify your iOS setup using diagnostic tooling and build tasks:

1. **Run Diagnostic Doctor**:
   ```bash
   ./gradlew :admob-cmp-core:doctorIos
   ```
   `doctorIos` inspects XCFramework download caches, Xcode project SPM references, `GADApplicationIdentifier` declarations, and `SKAdNetworkItems` keys.

2. **Execute Simulator Test Link**:
   ```bash
   ./gradlew :shared:iosSimulatorArm64Test
   ```

3. **Xcode Build & Run**:
   Open `iosApp.xcworkspace` in Xcode, build and run on an iOS simulator or device, and confirm initialisation succeeds with ATT and UMP prompts operating as configured.
