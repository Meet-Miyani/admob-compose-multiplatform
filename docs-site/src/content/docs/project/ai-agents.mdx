## Purpose of AI agent documentation

A large share of SDK integration happens through coding assistants,
and an assistant guessing at an API surface produces code that does
not compile against a frozen ABI. The repository ships dedicated
machine-readable instructions so coding assistants generate valid,
up-to-date integration code.

The hard rules in `AGENTS.md` provide explicit constraints so AI-generated
code aligns with the library's design and public API surface.

## Overview of AGENTS.md

`AGENTS.md` is the compressed, agent-targeted guide. It contains the
entry points (`rememberAdManager()` for Compose,
`AdMob.manager(context)` for Android, `LocalAdPlacements` for
shared placement lists), the canonical initialisation snippet,
a format-to-API table mapping each `AdFormat` to its controller,
composable and test ad IDs, the full-screen load/show pattern,
the banner and native sections including geometry and session
ownership, the app-open coordinator, the consent and
privacy-options rule, `testMode` versus
`strictTestMode` distinctions, executable iOS setup steps, and a
symptom-to-fix troubleshooting table. The file lives at
[`AGENTS.md`](https://github.com/Meet-Miyani/admob-compose-multiplatform/blob/master/admob-cmp/AGENTS.md).

`AGENTS.md` serves as a condensed index for agents, prioritizing common pitfall areas, while the full documentation site remains the complete reference.

## Agent configuration

For durable agent configuration in a repository using AdMob CMP, reference the published `AGENTS.md` in your project's assistant rules file (such as `.cursorrules`, `CLAUDE.md`, or custom system instructions):

```
Read https://github.com/Meet-Miyani/admob-compose-multiplatform/blob/master/admob-cmp/AGENTS.md
before writing any AdMob CMP code. Follow its API constraints exactly.
```

For one-off assistant prompts, include the URL directly in the prompt context.

## Available llms.txt bundles

`llms.txt` is a plain-text bundle of a site's documentation,
published at predictable paths so a language model can ingest
content without crawling and parsing HTML. This site
publishes three bundles:

| File | Purpose |
|---|---|
| [`/llms.txt`](/llms.txt) | Index. The entry point and table of contents for selective reading. |
| [`/llms-full.txt`](/llms-full.txt) | Full bundle. Every page, in order, for complete offline context. |
| [`/llms-small.txt`](/llms-small.txt) | Trimmed bundle, with project and changelog pages excluded for tighter context windows. |

The [API reference guide](/reference/api/) links to the generated Dokka declarations for exact signatures and platform availability.

Diagram components ship with prose equivalents that are included in the `llms.txt` bundle, allowing text-only models to process diagram contents without visual rendering.

## Search access and model training

The documentation site's crawler policy allows conventional search crawlers and explicitly permits retrieval by OAI-SearchBot, ChatGPT-User, Claude-SearchBot, Claude-User, PerplexityBot, and Perplexity-User. Training-oriented crawlers such as GPTBot, ClaudeBot, `anthropic-ai`, CCBot, Bytespider, Applebot-Extended, and Google-Extended are blocked.

Google-Extended is separate from Googlebot, so blocking it does not prevent normal Google Search crawling or eligibility for Google's search features. However, Google uses the same token to control some Gemini Apps grounding and model-improvement uses. The project's no-training policy therefore also limits that Gemini Apps grounding path. `llms.txt` remains a convenience for tools that choose to read it; it is not a special Google ranking signal.

## Common integration pitfalls

Key rules and constraints for AI coding tools when integrating AdMob CMP:

- Use `rememberAdManager()` in Compose or `AdMob.manager(context)` on Android rather than constructing `AdManager` implementations directly.
- Do not generate per-item placement IDs such as `"feed_item_$index"`. Reuse a static placement and give native sessions stable model-owned slot keys; never use list indexes or serialise a session/platform ad.
- Invoke `show()` from a UI-scoped coroutine rather than `GlobalScope`, as it suspends for the ad's full on-screen lifetime.
- Use flat test ID constants: `TestAdIds.ANDROID_BANNER`.
- Format `adLayout` DSL nodes as functions with named arguments: `headline(maxLines = 2)`.
- Note that `testMode = true` configures UMP consent debugging only; it does not serve test ads.
- Gate privacy-settings buttons on `PrivacyOptionsRequirementStatus.Required` rather than `ConsentStatus.Obtained`.
- Native sessions own platform objects and renderer leases. Report windows with the Compose helpers; do not add manual preload, acquire, release, token, or platform lookup code.
- Native video events fire on iOS (`GADVideoControllerDelegate`); Android does not emit native video events.
