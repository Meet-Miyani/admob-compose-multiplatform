## Native ads are session-owned

Native ads supply assets—headline, media, icon, body, advertiser, call to action—and the SDK
binds those assets to real platform native-ad views for impression and click tracking. In a feed,
the app owns stable *model* slots while AdMob CMP owns native platform objects, capacity, loading,
and the one renderer lease for each live ad. There is no consumer-managed inventory or platform
handle.

Use one named session for each logical feed owner. Keep that owner above individual rows: a row
may leave composition during recycling or a tab switch without implying that its native record
must be destroyed.

## Lazy list and grid feeds

Put a stable ad-slot key in the feed model—derived from neighbouring content identity, never from
the list index, page number, or a loaded ad. The viewport adapter scans the measured list and
reports visible, behind, and ahead slots to the session.

```kotlin
val placement = remember {
    AdPlacement(
        id = "feed_native",
        format = AdFormat.Native,
        androidAdUnitId = TestAdIds.ANDROID_NATIVE,
        iosAdUnitId = TestAdIds.IOS_NATIVE,
        // nativeTtl remains per-placement; it defaults to one hour.
    )
}
val listState = rememberLazyListState()
val session = rememberNativeAdFeedSession(
    sessionKey = "home-feed",
    listState = listState,
    itemCount = feed.size,
    slotAt = { index -> (feed[index] as? FeedItem.NativeSlot)?.let { NativeAdSlot(it.key, placement) } },
)

LazyColumn(state = listState) {
    items(feed, key = { it.stableKey }) { item ->
        when (item) {
            is FeedItem.NativeSlot -> NativeAdView(
                session = session,
                slotKey = item.key,
                placement = placement,
                layout = AdTemplates.feedCard,
                modifier = Modifier.fillMaxWidth().heightIn(min = 180.dp),
                loading = { NativeAdLoadingPlaceholder() },
                failure = { NativeAdLoadingPlaceholder() },
            )
            is FeedItem.Content -> ContentRow(item)
        }
    }
}
```

`NativeAdView` applies its outer `modifier` to the loaded renderer and to invalid, empty, loading,
failed, and renderer-contention placeholders. Put the stable row/cell footprint there; custom
`loading` and `failure` content should draw within that container rather than repeat its sizing
modifier. Removing the row and adding it later moves the reader's scroll position.

For a grid, use the `LazyGridState` overload. It reports the grid's measured item indexes through
the same bounded viewport adapter:

```kotlin
val gridState = rememberLazyGridState()
val gridSession = rememberNativeAdFeedSession(
    sessionKey = "discover-grid",
    gridState = gridState,
    itemCount = feed.size,
    slotAt = { index -> (feed[index] as? FeedItem.NativeSlot)?.let { NativeAdSlot(it.key, placement) } },
)

LazyVerticalGrid(columns = GridCells.Adaptive(180.dp), state = gridState) {
    items(feed, key = { it.stableKey }) { item ->
        when (item) {
            is FeedItem.NativeSlot -> NativeAdView(
                session = gridSession,
                slotKey = item.key,
                placement = placement,
                modifier = Modifier.fillMaxWidth().heightIn(min = 180.dp),
            )
            is FeedItem.Content -> ContentCard(item)
        }
    }
}
```

The lazy item key and `NativeAdSlot.key` should come from the same stable model identity. Stable
Compose keys preserve lazy-item identity, but they do not own or retain native platform objects;
the named session does. `NativeAdSession.state` reports each slot as `Empty`, `Loading`, `Ready`,
`Mounted`, `Retained`, or `Failed`; the composable does not start loads and never exposes a
platform ad.

## Inline article placement

An inline article placement is a distinct session, but still shares the application's global
governor with feed sessions. This is appropriate when the article has one stable native location
rather than a scrolling set of slots.

```kotlin
val inlineSlot = remember(article.id) {
    NativeAdSlot("inline-after-paragraph-3:${article.id}", articleNativePlacement)
}
val session = rememberNativeAdSlotSession(
    sessionKey = "article:${article.id}",
    slot = inlineSlot,
)

NativeAdView(
    session = session,
    slotKey = inlineSlot.key,
    placement = articleNativePlacement,
    layout = AdTemplates.medium,
)
```

`rememberNativeAdFeedSession` and `rememberNativeAdSlotSession` deactivate their session when
their composable host leaves composition. That is correct for a temporary tab exit: the default
inactive policy retains one anchor. When a logical destination is permanently discarded, call
`session.close()` (or `adManager.nativeAds.closeSession(key)`) from its owner. Do not put a
session or native platform object in saved state, a serializable ViewModel field, or navigation
arguments. ViewTube-style feeds should retain their stable feed and ad-slot models; the SDK
session owns the non-serializable platform objects.

## Capacity, retention, and requests

The default active session retains three records: one behind, the current visible slot, and one
ahead. Every list, grid, and inline session in the process shares one governor with a soft limit of
four and a hard limit of six **loaded plus reserved** ads; each session does not get its own four
or six. Visible demand may use hard-limit headroom; speculative work cannot pass the soft limit.
An inactive session retains at most one anchor, and inactive session metadata expires after 30
minutes. Memory pressure trims non-mounted records; mounted ads are never selected as victims.

`AdCachePolicy.maxSize` and `reloadAfterShow` are full-screen cache controls and remain independent
of native-session capacity. Configure the per-placement
`cachePolicy.expirationPolicy.nativeTtl` instead; its default is one hour. A reload after eviction,
TTL expiry, consent invalidation, clear, or memory pressure is expected. A reload merely because a
row recycled or a tab temporarily detached is not: verify stable session and slot keys first.

`NativeAdOptions.batching` controls request shape, not retention. `Sequential` is the default and
the only safe option for mediated or unknown inventory. `GoogleOnly` is an explicit assertion of
direct Google inventory and can request multiple ads, capped by Google at five. Five is a request
cap, not a memory target; a request may partially fill, and the governor still admits only bounded
demand.

## Layout DSL and media

Build custom layouts once with `remember`; DSL nodes are functions with named arguments, and
`adBadge()` is policy-required. `callToAction` controls appearance and insets; Android and iOS
display the creative-provided CTA text as supplied rather than replacing or uppercasing it.

```kotlin
val layout = remember {
    adLayout {
        column(modifier = AdModifier.fillMaxWidth()) {
            media(modifier = AdModifier.fillMaxWidth().aspectRatio(16f / 9f))
            headline(maxLines = 2)
            body(maxLines = 3)
            row(spacing = 8.dp) { icon(modifier = AdModifier.size(24.dp)); advertiser(); adBadge() }
            callToAction(modifier = AdModifier.fillMaxWidth())
        }
    }
}
```

The `Ready`, `Mounted`, and `Retained` states carry `NativeMediaInfo` when available, allowing a
row to reserve the creative's aspect ratio before attaching a renderer. Events are attached to a
specific admitted ad generation: stale callbacks and stale renderer releases cannot affect a
replacement record.

## Share Compose-resource typography with native ads

Use the same resource-backed `FontFamily` for Material text and selected native-ad text. Declare
each weight the app requests, even when they all point to one variable-font file:

```kotlin
@Composable
fun EditorialNativeAd(
    session: NativeAdSession,
    slot: NativeAdSlot,
    modifier: Modifier = Modifier,
) {
    val regular = Font(Res.font.newsreader_variable, FontWeight.Normal)
    val medium = Font(Res.font.newsreader_variable, FontWeight.Medium)
    val semiBold = Font(Res.font.newsreader_variable, FontWeight.SemiBold)
    val bold = Font(Res.font.newsreader_variable, FontWeight.Bold)
    val editorialFamily = remember(regular, medium, semiBold, bold) {
        FontFamily(regular, medium, semiBold, bold)
    }
    val typography = remember(editorialFamily) {
        Typography(
            headlineLarge = Typography().headlineLarge.copy(fontFamily = editorialFamily),
            titleLarge = Typography().titleLarge.copy(fontFamily = editorialFamily),
        )
    }
    val nativeLayout = remember(editorialFamily) {
        adLayout {
            column {
                headline(
                    maxLines = 2,
                    style = AdTextStyle(
                        fontSizeSp = 21f,
                        fontWeight = AdFontWeight.Bold,
                        fontFamily = AdFontFamily.FromCompose(editorialFamily),
                    ),
                )
                body(maxLines = 3) // Keeps the default system sans-serif family.
                adBadge()
            }
        }
    }

    MaterialTheme(typography = typography) {
        NativeAdView(
            session = session,
            slotKey = slot.key,
            placement = slot.placement,
            layout = nativeLayout,
            modifier = modifier,
        )
    }
}
```

`AdFontFamily.FromCompose` is the recommended resource-font path. Android resolves the requested
family and weight through Compose and applies the resulting `Typeface`; iOS reads the loaded
Compose font bytes, registers them internally with CoreText, and creates a matching `UIFont`.
Consumers do not need Android font XML, iOS `UIAppFonts`, or platform-specific names.

`AdFontFamily.Named` remains available for advanced cases where the font is already installed or
externally registered. Unsupported, corrupt, or not-yet-loaded Compose families fall back to the
platform system font without throwing. Compose/Skia, Android Views, and UIKit can still differ
slightly in font metrics and line breaking even when they use the same font file.

<Aside type="caution">
Android GMA Next-Gen has no native-video callback surface. iOS emits native video events through
`GADVideoControllerDelegate`; do not use those events for cross-platform product logic.
</Aside>

## Migration from the retired API

| Retired ownership | Session replacement |
|---|---|
| Retired per-placement native controller | `AdManager.nativeAds.session(sessionKey, policy)` |
| Manual preload | `NativeAdSession.updateWindow(window)`; the SDK derives demand |
| Manual acquire/release | Stable `NativeAdSlot.key`; `NativeAdView` gets an internal renderer lease |
| Token or platform lookup | No consumer handle; the coordinator owns the platform object |
| Retired available-inventory count and native cache capacity | Session state plus global/session policies |
| `NativeAdView(placement, itemKey, layout)` | `NativeAdView(session, slotKey, placement, layout)` |

The migration is intentionally not source-compatible. Do not build a compatibility wrapper that
recreates manual ownership: it would undermine bounded global admission and exact retirement.
