## Published versions

All published artifacts live under `dev.avinya.ads` on Maven Central:
`admob-cmp`, `admob-cmp-core`, `admob-cmp-compose`, and the
`dev.avinya.ads.admob-cmp.gradle.plugin` marker. The current
release is **2.0.1**.

| Version | Status | Highlights |
|---|---|---|
| 2.0.1 | Current | Native-ad custom fonts, renderer parity, synchronous leases, and grid sessions |
| 2.0.0 | Superseded | Release 2.0.0 |

## What changed in 2.0.1?

- **Compose resource fonts in native ads:** `AdFontFamily.FromCompose` now resolves resource-backed families in Android Views and UIKit without duplicate platform font configuration.
- **More reliable native rendering:** render leases are acquired synchronously with abandoned-composition cleanup, and loading, failure, and validation states preserve the caller's slot modifier.
- **Renderer parity:** preview, Android, and iOS now share image-background precedence and CTA inset behavior while retaining creative-provided CTA text.
- **Grid feed sessions:** `rememberNativeAdFeedSession` now accepts `LazyGridState` and shares the existing bounded viewport retention and prefetch policy.

## What changed in 2.0.0?

- **2.0.0 Release**: See [GitHub releases](https://github.com/Meet-Miyani/admob-compose-multiplatform/releases) for detailed changes.

## What changed in 1.1.1?

- **Cancelled banner loads no longer blank a live ad:** cancelling a banner load or refresh — a restarted effect, a resize, an explicit cancel — published `Idle`, which `BannerAdView` reads as "the ad is gone". A banner that was still loaded and on screen disappeared. The published state is now derived from the ad the controller actually still owns. See [Banner ads](/formats/banner/).
- **Ad state can no longer be resurrected after `clear()`:** the banner controller and native pool published their post-failure recovery state across two separate lock acquisitions, so a `clear()` landing in between was overwritten and the state reported `Loaded` for inventory that had just been released. Both now transition atomically.
- **Ads are no longer leaked when metadata reads fail:** if a platform response-info accessor threw after a successful load, the newly loaded banner or native batch was neither retained nor destroyed. Such ads are now torn down.
- **Ad SDK metadata is read on the main thread:** response and media information are captured during load rather than read back later from whichever dispatcher the caller used. This is historical context for the retired native-pool API; current native sessions publish media information with the slot state.
- **`testMode` warning no longer suppressed by consent debug IDs:** `AdDebugOptions.consentTestDeviceIds` configures UMP consent debugging only and never registers a GMA test device, so it no longer counts as evidence that test ads will be served. Configurations relying on it now correctly warn that live ads may be requested. See [Test ads and safety](/reference/compatibility/).
- **`AdPlacements` is genuinely immutable:** the placement list is copied at construction, so it can no longer be mutated behind Compose's back after being marked `@Immutable`.

## What changed in 1.1.0?

- **Gradle plugin for test linking:** The `dev.avinya.ads.admob-cmp` Gradle plugin provides automated header downloading and linker configuration for Kotlin/Native iOS test executables. See [Installation](/start/installation/) and [Troubleshooting](/reference/troubleshooting/).
- **Explicit banner geometry inputs:** `BannerAdController.load(geometry, sizePolicy, requestOptions)` requires host-supplied container dimensions. Passing `null` geometry for headless loads on unmeasurable containers fails fast rather than making width assumptions. See [Banner ads](/formats/banner/).
- **Request replay on refresh:** `refresh()` replays resolved request options from the preceding `load()` call, preserving custom `AdRequestOptions`.

## What changed in 1.0.2?

- **Core and Compose module separation:** The SDK was split into `admob-cmp-core` and `admob-cmp-compose` under the `admob-cmp` umbrella artifact, enabling non-Compose targets to consume controller APIs directly without Compose dependencies.

## What changed in 1.0.1?

- Maintenance release addressing minor implementation fixes across Android and iOS wrappers.

## What changed in 1.0.0?

- Initial public release of `dev.avinya.ads:admob-cmp` supporting six ad formats (banner, interstitial, rewarded, rewarded interstitial, app-open, native), UMP consent flow integration, mediation framework support, paid event streaming, and cinterop iOS bindings.

## Release record policy

Release notes document changes to public APIs, Maven coordinates, Gradle plugin behaviour, and supported toolchain versions. Internal refactoring and build configuration updates without public API impacts are tracked in git repository commits.
