## Distinguishing Kotlin klib compatibility from native framework linkage

When integrating or testing on iOS, it is vital to distinguish Kotlin klib ABI resolution from native iOS framework linkage:

- **Kotlin klib / ABI resolution:** `admob-cmp` publishes compiled Kotlin Multiplatform klibs, which include cinterop bindings (`admob-cmp-core-iosSimulatorArm64Cinterop-gmaMain.klib` and `umpMain.klib`). Klibs carry compiler metadata and ABI compatibility constraints across Kotlin toolchain versions.
- **Native iOS framework linkage:** Linking issues resulting in undefined Objective-C symbols (such as `_OBJC_CLASS_$_GADMobileAds` or `_OBJC_CLASS_$_UMPConsentInformation`) occur when the underlying Apple native frameworks (GoogleMobileAds, UserMessagingPlatform, or JavaScriptCore) are missing from the native link step.

<Aside type="caution">
From the Kotlin evolution principles: "klib binaries are backwards compatible starting with Kotlin 1.9.20." However, that guarantee **explicitly excludes cinterop klibs**: "The Kotlin cinterop klib binaries are still in Beta."

`admob-cmp` publishes cinterop klibs, so standard klib backward-compatibility guarantees do not cover them. If your project uses a newer Kotlin minor version than the version used to compile the library (Kotlin 2.3.20), verify your link step.
</Aside>

If an iOS build or test task fails with undefined `GAD*` or `UMP*` symbols:
1. **Xcode application build:** Ensure the official `GoogleMobileAds` and `UserMessagingPlatform` Swift packages are added to your Xcode target (see [iOS setup](/start/ios-setup/)).
2. **Kotlin/Native test execution:** Ensure the `dev.avinya.ads.admob-cmp` Gradle plugin is applied to configure test linker flags and framework paths (see [Installation](/start/installation/)).
3. **Missing JavaScriptCore:** Ensure `-framework JavaScriptCore` is included in `OTHER_LDFLAGS` if building a static framework without automatic linking.

Undefined native symbols indicate a native iOS framework or link configuration issue, not a Kotlin klib version mismatch.

## Do I need Compose Multiplatform?

Compose Multiplatform is required only for UI composable components (`BannerAdView`, `NativeAdView`, and `rememberAdManager`).

The core SDK module (`admob-cmp-core`) contains the underlying state machine, `AdManager`, full-screen controllers, placement models, consent handling, diagnostics, and event streams. Non-Compose UI layers or custom native UI wrappers can depend on `admob-cmp-core` directly without pulling in Compose Multiplatform dependencies.

The current library release is compiled against **Compose Multiplatform 1.11.1** and **Kotlin 2.3.20**. Consumer projects using Compose Multiplatform 1.11.1 fit naturally into this toolchain, whilst non-Compose projects depending strictly on `admob-cmp-core` should verify Kotlin compiler compatibility against 2.3.20.

## Which Google SDK versions are bound?

The library provides Kotlin bindings generated against specific Google Mobile Ads and UMP SDK versions:

| Platform | Native SDK | Bound Version | Delivery Mechanism |
|---|---|---|---|
| Android | Google Mobile Ads Next-Gen | 1.3.0 | Transitive Maven dependency |
| Android | User Messaging Platform | 4.0.0 | Transitive dependency via GMA |
| iOS | GoogleMobileAds | 13.7.0 headers | Added via Swift Package Manager (`13.x` major release) |
| iOS | GoogleUserMessagingPlatform | 3.1.0 headers | Added via Swift Package Manager (`3.x` major release) |

The bound iOS headers require that the resolved SPM major version matches the major version used during cinterop generation (`13.x` for GMA and `3.x` for UMP). An older or newer major version may fail at link time due to missing or modified Objective-C symbol definitions.

## Consuming the library on iOS

The iOS library targets Kotlin Multiplatform projects compiled into an iOS umbrella framework. Pure Swift iOS applications cannot import `admob-cmp` directly without a Kotlin Multiplatform wrapper module, because Kotlin/Native cinterop generates Kotlin-callable APIs rather than native Swift APIs.

For details on future platform capability targets, refer to the [Roadmap](/project/roadmap/).
