## Why do iOS Kotlin/Native tests fail with undefined GAD symbols?

When executing test suites such as `./gradlew :shared:iosSimulatorArm64Test`, the linker may report missing Objective-C symbols:

```
Undefined symbols for architecture arm64:
  "_OBJC_CLASS_$_GADMobileAds", referenced from: …
  "_OBJC_CLASS_$_GADBannerView", referenced from: …
ld: symbol(s) not found for architecture arm64
```

This error occurs because `admob-cmp` publishes header cinterop bindings rather than native binary frameworks. In an iOS application build, Xcode resolves `GAD*` and `UMP*` symbols from Swift Package Manager. However, a Kotlin/Native test binary is built directly by Gradle without invoking Xcode's Swift Package Manager resolution. Consequently, native framework search paths and linker flags must be supplied explicitly during test compilation.

Applying the `dev.avinya.ads.admob-cmp` Gradle plugin resolves this issue automatically for test tasks:

```kotlin
// shared/build.gradle.kts
plugins {
    id("dev.avinya.ads.admob-cmp") version "2.0.0"
}
```

```kotlin
// settings.gradle.kts
pluginManagement {
    repositories {
        mavenCentral()
        gradlePluginPortal()
    }
}
```

Key points when diagnosing this failure:
- Test binaries compile your entire shared source set. If any production file references `rememberAdManager`, `NativeAdView`, or consent APIs, those Objective-C bindings are included in the test binary link.
- Replacing `AdManager` with test stubs does not bypass the link step, because the binding symbols exist in the compiled module regardless of runtime invocation.
- Adding Swift packages to Xcode does not fix Gradle test binary linkage, because Gradle's Kotlin/Native compiler does not read Xcode project SPM dependencies.

<Aside type="danger">
Adding a Swift Package Manager dependency in Xcode will not resolve a `:linkDebugTestIos…` Gradle failure. Only the `dev.avinya.ads.admob-cmp` Gradle plugin configures linker options for Kotlin/Native test executables.
</Aside>

## Identifying link failure boundaries

The table below outlines common iOS link-time symptoms, their compilation context, and the corresponding resolution:

| Symptom | Compilation Context | Root Cause | Resolution |
|---|---|---|---|
| `Undefined symbol: _OBJC_CLASS_$_GAD*` | Xcode App Build | `GoogleMobileAds` SPM package is missing | Add the GMA Swift package in Xcode (see [iOS setup](/start/ios-setup/)) |
| `Undefined symbol: _OBJC_CLASS_$_UMP*` | Xcode App Build | `UserMessagingPlatform` SPM package is missing | Add the UMP Swift package in Xcode |
| `Undefined symbol: _OBJC_CLASS_$_GAD*` or `_UMP*` | Gradle `:linkDebugTestIos…` | Kotlin/Native test binary lacks SPM linking | Apply the `dev.avinya.ads.admob-cmp` Gradle plugin |
| `Undefined symbol: _OBJC_CLASS_$_JSContext` | Xcode or Gradle Build | JavaScriptCore framework is not linked | Add `-framework JavaScriptCore` to `OTHER_LDFLAGS` |
| `Undefined symbol: GADCurrentOrientation…` | Xcode or Gradle Build | GMA SPM package major version mismatch | Update the GMA Swift package to `13.x` |
| `__swift_FORCE_LOAD_$_swiftCompatibility56` | Gradle Test Build | Swift runtime compatibility libraries unlinked | Apply the Gradle plugin to append Swift toolchain library paths |

To determine the failing build phase: Gradle tasks starting with `link` and ending in `Test` indicate Kotlin/Native test execution, whereas `xcodebuild` failures indicate native Xcode framework assembly.

## How the Gradle plugin resolves test linkage

The `dev.avinya.ads.admob-cmp` Gradle plugin provides automated dependency management for test tasks:

1. Registers `downloadGmaIos` and `downloadUmpIos` tasks to download version-stamped GoogleMobileAds and UserMessagingPlatform XCFrameworks into `build/admob-cmp-ios-frameworks/` and verify their SHA-256 checksums.
2. Configures `link…Test…` tasks for `iosArm64` and `iosSimulatorArm64` to depend on framework downloads.
3. Appends test linker flags: `-F` for framework search paths, `-framework GoogleMobileAds`, `-framework UserMessagingPlatform`, `-framework JavaScriptCore`, and `-L` for Swift runtime compatibility libraries.
4. Leaves production application framework binaries untouched so Xcode manages SPM linking natively.
5. Registers the `doctorIos` diagnostic task.

To populate caches or verify setup manually:

```bash
./gradlew :shared:downloadGmaIos :shared:downloadUmpIos   # Pre-populate framework cache
./gradlew :admob-cmp-core:doctorIos                       # Run diagnostic check
```

## Understanding SDK_NOT_READY and CONSENT_REQUIRED errors

The library defines two typed error constants in `AdErrorCode` for pre-request validation gates. All other errors are passed directly from platform SDK responses:

| Code | Value | Cause | Resolution |
|---|---|---|---|
| `AdErrorCode.SDK_NOT_READY` | `"sdk_not_ready"` | `initialize` has not completed | Verify `adManager.status` is `AdManagerStatus.Ready` before requesting ads |
| `AdErrorCode.CONSENT_REQUIRED` | `"consent_required"` | UMP consent policy blocks ad requests | Execute `gatherConsentAndInitialize` or check `canRequestAds` |

Platform numeric error codes returned via `AdError`:

| Platform Codes | Category | Retry Recommendation |
|---|---|---|
| Android `3`, iOS `1` | No fill (inventory unavailable) | Non-retryable immediately; request again at the next natural application event |
| Android `0`, `2`, iOS `2`, `5`, `11` | Network / internal / timeout | Retryable via `AdRetryPolicy` (default `maxAttempts = 2`) |

`AdError` provides `code`, `message`, `domain`, and `responseInfo`. Inspecting `responseInfo.adNetworkResponseInfos` reveals specific adapter responses when using mediation.

## Android startup crashes and manifest configuration

The Google Mobile Ads SDK requires an AdMob application identifier declared in `AndroidManifest.xml`. Omitting this metadata entry results in a startup crash:

```xml
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-xxxxxxxxxxxxxxxx~yyyyyyyyyy" />
```

Ensure the value is an AdMob **application ID** (containing a tilde `~`), not an ad unit identifier (which uses a forward slash `/`).

## Banner rendering issues

If a banner composable or view renders no content, check the following conditions:
1. `adManager.status` has reached `AdManagerStatus.Ready`.
2. For placements configured with `BannerRefreshPolicy.Manual`, verify that `adManager.banner(placement).refresh()` has been invoked.
3. Headless `load()` calls require valid `BannerGeometry` on platforms unable to resolve container width automatically.
4. Verify that the request did not encounter an ad fill error.

## Native ads reload after a tab switch or scroll

A temporary row recycle or tab exit should detach a renderer, not reload a retained native ad. Keep one stable `NativeAdSession` above the feed rows, use model-owned `NativeAdSlot.key` values, and let the Compose helper call `deactivate()` on temporary composition loss. A reload is expected after TTL expiry (one hour by default), eviction under memory pressure, consent invalidation, clear, or permanent `close()`—not after mere detachment.

If a row is empty or loading, retain its placeholder geometry. Inspect `session.state` and `adManager.nativeAds.state`; do not introduce manual platform-object ownership to force a reload.

## Controller reentry and initialisation rules

`FullScreenAdController.show()` is non-reentrant. Attempting to call `show()` whilst an ad is active on screen returns `AdShowResult.NotReady`. Await the completion of the active `show()` call before invoking presentation again on the same controller.

Calling `AdManager.initialize()` multiple times with identical `AdConfig` parameters returns the existing initialisation result. Invoking `initialize()` with conflicting configuration parameters logs a warning without modifying the active singleton configuration, as underlying platform SDKs do not support runtime re-initialisation.

## Constructor validation errors

`AdPlacement` validates configuration parameters upon construction:
- Throws `IllegalArgumentException` if `id` is blank or `cachePolicy.maxSize` is less than 1.
- Throws `IllegalArgumentException` if `strictTestMode` is enabled and a production ad unit ID is passed instead of an official Google test unit ID.

## Platform video event support

iOS emits native video lifecycle events via `GADVideoControllerDelegate`. Android GMA Next-Gen SDK does not expose video callbacks on native ads, so Android emits no video events. `NativeMediaInfo` is carried by ready, mounted, and retained session state when available and can be used for cross-platform layout decisions.

## Automated iOS diagnostic tool

Run `doctorIos` to verify local iOS configuration, framework caches, and plist declarations:

```bash
./gradlew :admob-cmp-core:doctorIos
./gradlew :admob-cmp-core:doctorIos -PadmobCmp.xcodeproj=path/to/project
```
